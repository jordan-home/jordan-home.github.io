Prompt Engineering 基础指南

跟 LLM 高效沟通的提示词技巧：角色设定 / few-shot / 任务分解 / 输出格式约束。

Prompt Engineering 不是”玄学”，是有可学的方法的。

核心原则

1. 给具体角色

你是一位有 10 年经验的前端工程师，擅长代码审查。

比”帮我写代码”好 10 倍。

2. 明确任务

请审查以下代码：
- 找出 bug
- 给出改进建议
- 按"严重程度"排序

不要”看看这段代码”。

3. 提供上下文

我们项目用 React 18 + TypeScript，严格模式。
这是个表单组件，处理用户注册。

LLM 不知道你的项目背景，给它。

4. few-shot（给例子）

示例输入：苹果
示例输出：🍎 红色，常见水果

现在输入：香蕉

LLM 看例子学最快。

5. 输出格式约束

请用以下 JSON 格式输出：
{"issues": [{"severity": "high", "line": 12, "desc": "..."}]}

比”列出问题”准确。

6. 分步思考（CoT）

让我们一步步思考：
1. 先找出所有变量声明
2. 再检查作用域
3. 最后判断

复杂任务要让 LLM “显式推理”。

高级技巧

反向 prompt

“请不要做 X” 比 “请做 Y” 更稳定。

自我审视

“在最后检查一遍你的答案，确保无错。”

Temperature 调节

  • 创意写作：0.7-1.0
  • 代码 / 事实：0-0.3

常见错误

  • 期望 LLM 知道你的私有信息（不知道的）
  • 一个 prompt 解决多个独立问题（拆分）
  • 不验证 LLM 输出（必须验证）

LLM 是工具，用对姿势才能发挥威力。
